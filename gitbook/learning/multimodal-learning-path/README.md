# 多模态初学路径

*2026-09-22 · 学习路线*

标签：多模态 · 深度学习 · 计算机视觉 · 语言模型 · 学习方法

> 摘要：从训练基础出发，依次学习 ViT、CLIP 和 LLaVA，完成一个包含图文检索、问答与错误分析的小项目。

先做图文检索，再做图文问答，是一条范围比较清楚的多模态入门路线。前者研究图片与文字怎样匹配，后者研究视觉信息怎样参与文字生成。沿着这两个任务，可以把视觉编码器、图文对齐和语言模型的作用分开理解。

这篇路线从训练基础补起，适合会一点 Python、准备接触或刚接触深度学习的读者。第一轮的目标是读懂一条样本：图片怎样进入模型，训练时哪些参数接受更新，输出的答案又错在什么地方。音频、视频和图像生成留到后面选择方向时再展开。

## 一、从检索到问答

手里有一组照片，输入一句话找到对应的图片，再问图片里有什么、物体之间是什么关系。完成这个小应用，可以按下面的顺序学习。

| 阶段 | 要回答的问题 | 留下的成果 |
| --- | --- | --- |
| 训练基础 | 损失怎样影响参数？训练和验证有什么区别？ | 一个能训练、保存、重新加载的小模型 |
| 视觉表示 | 一张图片怎样变成一串向量？ | 一张标有张量形状的 ViT 数据流图 |
| 图文对齐 | 图片和文字为什么可以比较相似度？ | 一个 CLIP 图文检索实验 |
| 图文问答 | 视觉信息怎样参与文字生成？ | 一个 VLM 推理脚本及输入输出记录 |
| 实验与评测 | 一次修改究竟改善了什么？ | 一份有基线、对照和失败案例的报告 |

这里的 VLM 是 Vision-Language Model，即视觉语言模型。下文谈到“图文问答模型”时，主要指能够结合图片生成文本的这一类模型。

## 二、基础补到什么程度，可以开始？

最先需要补齐的是训练过程。至少能解释一次前向计算、损失计算、反向传播和参数更新，并能分清训练集、验证集和测试集各自承担什么任务。

数学可以结合训练过程来学：矩阵乘法解释数据怎样经过一层网络，导数和链式法则解释参数怎样更新，概率与交叉熵帮助理解模型怎样给候选答案分配分数。

用 PyTorch 训练一个小型图像分类模型，就能练到这些内容：画出训练损失和验证指标，保存权重，再重新加载做一次预测。调试时可以尝试让模型拟合几十个样本，检查训练链路是否通畅；之后仍然要看独立验证数据上的表现。程序跑通后，再换一组数据或修改一层网络，练习定位和修复随之出现的问题。

### CS231 和 CS336 怎么穿插？

视觉这一侧，可以沿着 CS231n 的分类、反向传播、优化、CNN、Attention 与 Transformer 往下学，再接视觉语言内容。相关笔记放在 [CS231 学习记录](../cs231/README.md)中。[CS231n 2025 课程安排](https://cs231n.stanford.edu/2025/schedule.html)

语言这一侧，先理解分词、词向量、因果注意力和下一个 token 预测，再尝试实现一个小型语言模型。CS336 的第一个作业覆盖了分词器、模型结构、优化器和最小语言模型训练；后面的系统、数据与扩展规律内容，可以在相应问题出现时继续深入。课程本身对 Python、深度学习和系统知识有前置要求，标题里的“从零构建”不等于编程零基础。[CS336 2025 课程与作业](https://cs336.stanford.edu/spring2025/)

这里引用 2025 版课程，是为了固定一套可以对照的材料。学习时尽量让讲义、视频和作业保持同一版本。

两门课不必全部学完再开始多模态实验。能看懂一个 batch 怎样经过网络，查清张量形状，解释损失在优化什么，就可以尝试图文任务。之后遇到梯度、注意力或显存问题，再回到相应课程内容。

## 三、先学 ViT：图片怎样进入 Transformer？

ViT 把图像切成固定大小的 patch，将每个 patch 映射成向量，加上位置信息，再交给 Transformer。以一张 224×224 的图像和 16×16 的 patch 为例，共得到 14×14，也就是 196 个图像块；原始分类结构还会加入一个分类 token。[ViT 原论文](https://arxiv.org/abs/2010.11929)

```text
图像 → 图像块 → 向量映射与位置编码 → Transformer → 视觉特征
```

在数据流图上标出张量形状。例如，输入常记成 `[B, 3, H, W]`，图像块经过映射后可以表示成 `[B, N, D]`：B 是批大小，N 是图像块数量，D 是特征维度。是否保留额外 token、最终取哪一层输出，要结合具体实现查看。

加载一个预训练 ViT，做一次前向计算，打印图片变成序列前后的形状，再比较中间特征和分类输出。对照这次运行，画出自己的数据流图。图像分辨率或 patch 大小变化时，图像块数量会怎样变化，也可以在图上推算。

CNN 的卷积、局部性和下采样值得学，它们有助于理解视觉表示。进入 ViT 之前，把这些概念弄清楚即可，视觉模型的发展史可以在后续学习中逐步补全。

## 四、再学 CLIP：图片和文字怎样对上？

图片和文字分别经过编码器，并不自动就能比较相似度。CLIP 用图文配对数据训练图像编码器和文本编码器，让两边的表示能够匹配。对一批成对的图片和描述，对比学习会提高匹配图文的相似度，并相对于批内其他配对拉开差距。训练完成后，文字就可以用来检索图片，也可以描述候选类别，进行零样本分类。[CLIP 原论文](https://arxiv.org/abs/2103.00020)

### 第一个实验：用一句话找图片

可以准备一两百张内容明确的图片，先从物体、颜色、场景这类容易判断的描述开始。固定图像预处理和模型权重，预先保存图片特征；查询时，把文字转成特征，与图片特征计算相似度，返回排名靠前的结果。官方实现已经提供编码图片、编码文本和计算相似度的示例，适合从这里开始拆解。[CLIP 官方代码](https://github.com/openai/CLIP)

实验跑通后，逐渐提高查询难度：

- 从“杯子”改成“红色杯子”，观察属性是否起作用。
- 加入主体相似、背景不同的图片，观察模型更依赖哪一部分。
- 加入数量或空间关系的描述，记录哪些差异容易被忽略。

如果使用原始 CLIP，先用英文查询建立基线。它的官方模型卡说明，模型没有针对英语之外的语言进行专门训练和评估；中文检索应另行选择支持中文的模型并验证效果。[CLIP 模型卡](https://github.com/openai/CLIP/blob/main/model-card.md)

### 第二个实验：看懂相似度矩阵

构造一个包含 B 对图文的小批次。两边的特征归一化后，计算一个 B×B 的相似度矩阵，其中第 i 行、第 j 列对应第 i 张图片与第 j 段文字的相似度。只要图文按对应顺序排列，正确配对就在主对角线上。对照矩阵检查排序错误的例子，看看哪一段文字获得了更高的分数。

然后实现损失：分别沿图片找文字、文字找图片两个方向计算交叉熵，再取平均。这个小实验用来理解 CLIP 的训练目标，效果与原论文的大规模预训练有很大距离。批大小、负样本和温度参数对训练的影响，也可以从这个矩阵继续研究。[CLIP 论文中的训练目标与伪代码](https://arxiv.org/abs/2103.00020)

CLIP 给图文匹配打分，本身没有负责逐字生成答案的语言解码器。图文问答还需要引入生成文本的模型。

## 五、接上 LLaVA：视觉信息怎样参与回答？

LLaVA 将视觉编码器与语言模型连接起来：

```text
图片 → 视觉编码器 → 投影层 → 视觉特征序列 ─┐
                                        ├→ 语言模型 → 文本回答
问题 → 分词与文本嵌入 ────────────────────┘
```

视觉编码器提取图像信息，投影层把这些特征映射到语言模型所需的维度，语言模型结合视觉信息和问题生成答案。维度接上只是结构条件，怎样利用图片仍然依赖训练。

原始 LLaVA 采用 CLIP 视觉编码器、线性投影层和语言模型：第一阶段冻结视觉编码器与语言模型，训练投影层；第二阶段保持视觉编码器冻结，更新投影层与语言模型，学习遵循视觉指令。LLaVA 1.5 则采用两层 MLP 连接器，并调整了视觉分辨率和训练数据。读论文与代码时，要核对自己讨论的是哪一版。[原始 LLaVA 论文](https://arxiv.org/abs/2304.08485)、[LLaVA 1.5 论文](https://arxiv.org/abs/2310.03744)

先选一个设备能够运行、文档完整的模型完成推理，保存图片、问题、回答以及推理配置。图像处理器和对话模板应与权重配套。LLaVA 的实现文档对不同模型的提示格式和输入处理有专门说明，不同仓库的调用方式不能随意拼接。[Transformers 的 LLaVA 文档](https://huggingface.co/docs/transformers/model_doc/llava)

拿这条运行成功的样本对照代码，检查输入和训练设置：

1. 图片怎样缩放、裁剪和归一化？模型实际接收到的画面还保留哪些细节？
2. 取的是视觉编码器哪一层的输出？送给语言模型的视觉序列有多长？
3. 视觉特征怎样与问题一起进入语言模型？占位符、位置和掩码怎样对应？
4. 训练时哪些参数更新？哪些位置参与损失计算？

损失计算可以单独画一条训练样本来理解。对于只监督回答部分的指令微调配置，问题会作为上下文参与计算，但其标签位置被屏蔽。把参与监督的位置标出来，再对照模块的冻结设置，追踪梯度怎样从损失传到待训练的参数。

## 六、把两个演示变成一个完整的小项目

把前面的检索和问答脚本放进同一个小项目，为它们补上固定数据和评价规则。

先建立固定图片库，为检索查询标出相关图片，再为其中一部分图片写出可以核对答案的问题。素材可以来自自己拍摄的物品、日常场景或允许使用的公开数据。问题尽量具体，例如颜色、数量、可见文字和相对位置；遇到图中无法确定的事情，也明确标注“无法判断”。

开发阶段用一组图片调整程序、提示词和处理方式，再留出另一组图片做最终检查。同一图片的不同问法、相近裁剪以及近重复图片，尽量放在同一组里。图片规模很小时，这套划分主要帮助自己形成实验习惯，结果只代表当前样本。

### 检索：先固定什么叫“找对”

可以记录“前 5 张结果中至少出现一张相关图片”的查询比例，并把它明确写作 Hit@5。如果采用 Recall@5，则先写清相关图片的标注方式和计算定义：在一个查询有多张相关图片时，命中一张与找回全部相关图片是不同的要求。

候选图片库也要固定。更换查询描述、图像预处理或模型时，保留相同的查询集和候选集，才能比较变化；单条查询的改善不能代替整组查询的结果。

### 问答：答案流畅之后，还要核对内容

先约定评分规则，再看模型输出。颜色和数量可以允许常见同义表达，但不能因解释写得长就加分。无法回答的问题，要检查模型是否会承认信息不足。

把错误按表现归类：看漏目标、读错文字、数量错误、空间关系错误，以及提到图中不存在的物体。后一种问题通常称为物体幻觉，POPE 专门研究了这类问题的评估。[POPE 论文](https://arxiv.org/abs/2305.10355)

再做一个小对照：对那些必须依赖图片才能回答的问题，保持问题不变，替换成另一张内容明确不同的图片，检查答案是否按证据变化。这个实验可以提供模型是否利用图片的线索，但单次回答变化不足以证明模型已经理解了视觉关系。

### 一次只改一个因素

比如只修改问题表述，或在模型支持的范围内调整图像处理方式。保持模型权重、数据划分和生成参数一致，比较开发集表现，确定方案后再检查预留的测试图片。

报告里至少保留：模型与依赖版本、数据划分、输入处理、生成设置、评分规则、整体结果，以及几个解释清楚的成功和失败案例。如果做了训练，再记录随机种子、训练参数和权重保存位置。

第一轮做到推理与评测即可。继续接触训练时，先确定要解决哪类错误，再选择相应模块做小实验。例如冻结编码器，只训练轻量模块，观察训练指标和验证指标是否同步变化。

实验规模还受设备限制。小型图文编码器的少量推理可以先在 CPU 上调通，速度通常较慢；生成式 VLM 的显存需求还取决于权重精度、视觉序列长度和文本长度。先查所选模型的官方要求，再决定本地或远程运行，没有一个适用于所有模型的显存门槛。

## 七、怎样安排节奏，以及接下来学什么？

已有基本 PyTorch 经验的话，第一轮可以按六到八周、每周约六至十小时安排。训练循环和注意力还不熟悉，就多留些时间补基础。

| 时间 | 主要任务 | 阶段检查 |
| --- | --- | --- |
| 第 1—2 周 | 补训练基础、注意力和 ViT | 小模型能训练；能解释视觉特征形状 |
| 第 3—4 周 | 跑通 CLIP 检索，理解对比损失 | 有固定查询集和第一批失败案例 |
| 第 5—6 周 | 跑通图文问答，追踪 LLaVA 数据流 | 能解释一条样本的输入、监督与输出 |
| 第 7—8 周 | 完成一次对照实验并整理报告 | 有基线、评价规则和可复查的结果 |

读论文也可以跟着实验走。第一遍只回答“任务是什么、输入输出是什么、训练信号是什么”；第二遍对照代码补结构与数据处理；第三遍再看实验设计，判断作者的结论由哪些对照支撑。暂时看不懂的术语先记下所在位置，有了具体问题再追。

完成这轮之后，可以从自己最在意的错误出发选方向。总是读错图片里的文字，可以继续研究文字识别与文档理解；关心动作和事件，就转向视频里的时间信息；关心语音交互，就去补音频表示与序列建模；想生成图片，则另开一条生成模型路线。
